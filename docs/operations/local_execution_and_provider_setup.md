## 4. Joined programme and weekly workflow

The joined driver, finite free-discovery callback and separate follow-on review scopes are implemented. `NeuraFlow-Dropshipper-Research` is installed and enabled in Windows; the repeat-install comparison preserved the matching task, and a scheduled check returned0 with no second research writer observed. Neither kills an already dispatched request. Keep this one task and the kernel guard; do not create independent competing research writers. After a genuine saved fixed point, weekly discovery can proceed without cloning the old product pool; due old/new work rotates by its last serviced time.

The complete operator experience below still needs whole-pool, fresh-discovery, recurring financial/history and private-release acceptance; a joined function is not completed operation.

Manual and scheduled AI work use the same validated installed program selected in `config/ai/codex_luna.json`, and the connection checker uses that same selector. The explicit path does not change the chosen account/model or create a new saved request. A missing or incompatible program defers only new AI launches; saved answers and other ready work continue. Preserve failed execution receipts and prepare only an inspected, reconciled request for a deliberate retry. See [AI connection and recovery](providers/codex_luna_connection.md#one-executable-for-manual-and-automatic-work).

## 6. Problems and the next useful action

This table is the operating response contract. Decision/binding checks, supplier effort, saved-job recovery, partial internal files, account routing and scheduling are connected locally. Draft-only machine storage and owner downloads have actual separate proof. Complete whole-pool operation, recurring recovery and approved client release remain under acceptance; the table does not claim that every fallback has been proved in unattended service.

| Situation | Operator/program response |
|---|---|
| Fewer than ten eligible products for one issue | Preserve draft, exact counts and reasons; discuss that shortfall. Continue independent issues/useful work; no weak padding or silent smaller issue. |
| Source blocked or chart sparse | Record actual route/product attempt, stage/status/time; unavailable or insufficient is not zero demand. Try only a finite permitted alternative when useful. |
| Shared outage across routes | Group the common observed transport/access problem; do not retry every product/account. Use valid saved work or another ready lane; schedule one bounded due recovery probe. |
| Repeated products/queries | Reuse exact saved work, use alias/function history, update feedback/cooldown and select a useful new area. No default ever-deeper paging. |
| Possibly running or uncertain paid submission | Recover original account/run/receipt before any new POST. Other saved analysis continues. |
| Unknown read fees | Retain existing holds and show uncertainty; do not require every historical read settled before all work can proceed. |
| Original key or provider period expires | Keep the original account/run and verify replacement credentials for that account. Any new billed read needs explicit current-period funding while original fees/holds/lifetime limits remain; do not move the job or create credits. |
| Supplier/fee/dispatch/photo unknown | Show that exact limitation and preserve useful product work. No invented supplier capability or photo; no new mandatory certification. |
| Every attempted supplier route fails or gives nothing usable | Preserve exact internal receipts/next trigger. After real bounded effort, include an otherwise eligible product with “Supplier search did not produce any usable results.” Do not claim supply is absent or call failed searches successful. |
| Model limit or interrupted process | Preserve accepted siblings/results; reconcile owned execution before the finite allowed retry. No paid fallback or unchanged repeated calls. |
| Facts saved but writing/rendering partly fails | Preserve frozen core facts, internal workbook and valid separate language stages. A local failed chunk, correction or problem-record save retains the completed language and records a fixed safe reason, including when a problem record could not save. Resume missing work from exact saved answers; no second model call or rerender of valid unchanged English is needed. Required bilingual issue stays incomplete until both editions pass. |
| Owner unavailable / client email missing | Pause only transport/approval/client activation; continue dependency-ready internal work. |
| Ongoing language not chosen | Pause only the third language package; first two complete bilingual issues can proceed independently. |
| Render/upload/index conflict | Preserve prior valid release/incomplete artifacts. Check whether the exact approved activation already committed before rejecting its original saved ETag; otherwise reconcile genuine conflict, never silently overwrite or refresh approval. |
| Late/cancelled/replaced issue | Recheck affected novelty, language ordinal, source expiry and remote reservations. Published availability stays in history. |
| Material supply/budget conflict | Provide measured cost/yield/queue numbers and options. No automatic purchases or silently changed five-of-ten inclusion/four-level source priority/ten-product floor. |
| A few cents of variation | Absorb within approved actual funded limits and finite scope; do not interrupt for penny-level approvals. |
| Canonical record cannot be saved/trusted | Do not launch dependent charged/model work without durable intent. Retain outputs/last committed position; hosted reports remain intact. If the authoritative event saved and only the optional index failed, retain the successful application and rebuild the index; do not repeat external work. |
| All remaining work waits, limits ended or computer was off | Save queue/consumption/trigger. Resume same-period remaining work or carry useful backlog into one new due-period envelope. No unchanged loop, accumulated missed allowances, cancellation bypass or promise of local work while off. |

A problem record includes expected/actual, affected action/product/issue, confirmed versus suspected cause, safe evidence, possible remote charge/running state and next trigger. Group repeated route failures; do not ask the same unanswered setup question repeatedly.

The [action-level matrix](benchmarks/2026-10-03/execution_specification.md#2117-action-level-fallback-and-continuation-contract) still includes later recovery work; it is not a claim that every lane is automated. P2 keeps valid products moving when a sibling fails, reuses exact saved review answers, ties brand corrections and supplier effort to the right product, and retains a successful main-record save even when its optional quick-view index fails. Different ready tasks can proceed during a wait; running blindly again is not recovery. If the main saved history cannot be trusted, dependent changes wait without deleting old work or affecting already-hosted reports.
